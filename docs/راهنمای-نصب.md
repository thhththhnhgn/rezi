## مرحله ۱ — آماده‌سازی کد

کد جدید روی برنچ `arena/019facf9-panel-gaming` است. Railway معمولاً از برنچ
`main` دیپلوی می‌کند، پس یکی از این دو راه را انتخاب کنید:

### راه الف — مرج کردن در main (پیشنهادی)

در گیت‌هاب وارد ریپازیتوری شوید:

```
https://github.com/xtjjtx/panel.gaming
```

1. بالای صفحه پیام **Compare & pull request** را می‌بینید → روی آن بزنید
2. مطمئن شوید مسیر این‌گونه است: `base: main` ← `compare: arena/019facf9-panel-gaming`
3. دکمه **Create pull request** را بزنید
4. سپس **Merge pull request** → **Confirm merge**

اگر پیام Compare را نمی‌بینید، مستقیم این لینک را باز کنید:

```
https://github.com/xtjjtx/panel.gaming/compare/main...arena/019facf9-panel-gaming
```

### راه ب — دیپلوی مستقیم از همین برنچ

اگر نمی‌خواهید مرج کنید، در مرحله ۲ بعد از ساخت سرویس بروید به
**Settings → Source → Branch** و برنچ را روی
`arena/019facf9-panel-gaming` بگذارید.

## مرحله ۲ — ساخت سرویس در Railway

1. وارد [railway.app](https://railway.app) شوید (با گیت‌هاب لاگین کنید)
2. **New Project** را بزنید
3. گزینه **Deploy from GitHub repo** را انتخاب کنید
4. ریپازیتوری `panel.gaming` را انتخاب کنید
5. اگر اجازه دسترسی خواست، **Configure GitHub App** را زده و به ریپو دسترسی بدهید

Railway خودش فایل `Dockerfile` را تشخیص می‌دهد و بیلد را شروع می‌کند.

> ⏱ **بیلد اول حدود ۲ تا ۴ دقیقه طول می‌کشد** چون آخرین نسخه Xray-core را
> از گیت‌هاب دانلود می‌کند.

**نکته:** بیلد اول ممکن است fail شود چون هنوز متغیرها را نگذاشته‌اید.
این طبیعی است — مرحله بعد را انجام دهید و دوباره دیپلوی کنید.

## مرحله ۳ — تنظیم متغیرها

روی سرویس کلیک کنید → تب **Variables** → دکمه **Raw Editor**.

این متن را کپی کرده و داخل کادر بچسبانید:

```env
ADMIN_USER=admin
ADMIN_PASS=T5haslvMDz31D3xKZLmFpZCu
SECRET_KEY=c9f41bcb3f79ec218dbdba6e04db6773c5d5317b51d48f33e36b6350a6fc0497
PATH_SECRET=cd439dffc7ec780b5a091291fed43dc3
DB_PATH=/data/ultra.db
```

سپس **Update Variables** را بزنید.

### معنی هر متغیر

| متغیر | کارش چیست |
|-------|-----------|
| `ADMIN_USER` | نام کاربری ورود به پنل |
| `ADMIN_PASS` | **رمز پنل.** بدون این، هیچ لاگینی قبول نمی‌شود |
| `SECRET_KEY` | توکن‌های نشست را امضا می‌کند |
| `PATH_SECRET` | مسیرهای تونل را مخفی و تصادفی می‌کند |
| `DB_PATH` | محل دیتابیس — باید روی ولوم باشد |

> 🔐 **رمزهای بالا مخصوص شما تولید شده‌اند.** جایی امن ذخیره‌شان کنید.
> اگر خواستید عوضشان کنید، با این دستور رمز جدید بسازید:
>
> ```bash
> python3 -c "import secrets; print(secrets.token_urlsafe(18))"
> ```

### متغیرهای اختیاری

بعداً اگر خواستید اضافه کنید:

| متغیر | کاربرد |
|-------|--------|
| `CF_WORKER_HOST` | آدرس ورکر کلودفلر (بدون `https://`) |
| `SEED_USER` | نام اولین کاربری که خودکار ساخته می‌شود |
| `XRAY_LOGLEVEL` | برای دیباگ روی `info` بگذارید |

## مرحله ۴ — اضافه کردن ولوم (مهم!)

فایل‌سیستم Railway موقتی است. **بدون ولوم، با هر دیپلوی تمام کاربران،
سهمیه‌ها و آمارتان پاک می‌شود.**

1. سرویس → تب **Settings**
2. بخش **Volumes** → دکمه **New Volume**
3. در فیلد **Mount path** بنویسید:

```
/data
```

4. تایید کنید

حجم ۱ گیگابایت کاملاً کافی است — دیتابیس حتی با صدها کاربر چند مگابایت
بیشتر نمی‌شود.

> ✅ اگر درست انجام شده باشد، در لاگ دیپلوی **نباید** پیام
> `falling back to /tmp/ultra.db` را ببینید.

## مرحله ۵ — ساخت دامنه

1. سرویس → **Settings** → بخش **Networking**
2. دکمه **Generate Domain** را بزنید
3. Railway آدرسی مثل این می‌دهد:

```
panel-gaming-production-a1b2.up.railway.app
```

این آدرس را یادداشت کنید. TLS خودکار فعال است، پس همه چیز HTTPS است.

## مرحله ۶ — ورود به پنل

مرورگر را باز کنید:

```
https://آدرس-شما.up.railway.app/panel/
```

با این اطلاعات وارد شوید:

* **Username:** `admin`
* **Password:** همان `ADMIN_PASS` که تنظیم کردید

### تست سلامت

قبل از ورود می‌توانید این‌ها را چک کنید:

| آدرس | نتیجه درست |
|------|-------------|
| `/health` | متن `ok` |
| `/` | سایت شرکت رندرینگ (سایت پوششی) |
| `/panel/` | صفحه ورود نئونی |
| `/vless` | سایت پوششی (نه ارور!) |

> 🕵️ اگر آدرس اصلی سایت یک شرکت انگلیسی نشان می‌دهد، **درست کار می‌کند**.
> این سایت پوششی است تا اسکنرها نفهمند اینجا پروکسی است.

## مرحله ۷ — ساخت کاربر و گرفتن کانفیگ

1. در پنل به صفحه **Players** بروید
2. دکمه **+ New Player** را بزنید
3. پر کنید:

| فیلد | توضیح | مثال |
|------|-------|------|
| Username | حروف انگلیسی، عدد، `.` `_` `-` | `ali` |
| Quota (GB) | سهمیه حجم، `0` = نامحدود | `100` |
| Expires (days) | اعتبار به روز، `0` = همیشگی | `30` |
| Note | یادداشت شخصی | `موبایل علی` |

4. **Save** را بزنید

حالا روبروی کاربر دکمه **CONFIGS** را بزنید. اینجا می‌بینید:

* **Links** — ۱۲ کانفیگ آماده (۶ پروتکل × مستقیم و کلودفلر)
* **Subscription** — لینک اشتراک برای هر نوع کلاینت
* **Achievements** — دستاوردهای کاربر

هر کانفیگ دو دکمه دارد: **COPY** (کپی) و **QR** (کد QR برای اسکن).

## مرحله ۸ — اتصال با کلاینت

### هر اشتراک شامل هر دو دامنه است

سرویس شما معمولاً روی دو نام جواب می‌دهد: دامنه شخصی و دامنه اصلی
`*.up.railway.app`. هر دو در اشتراک می‌آیند — یعنی به‌جای ۵ کانفیگ،
**۱۰ کانفیگ** (هر پروتکل روی هر دو دامنه).

اگر یکی از دامنه‌ها برای اپراتور کاربر فیلتر شد، دیگری از قبل در
کلاینتش هست و فقط کافی است سوییچ کند.

دامنه Railway از متغیر `RAILWAY_PUBLIC_DOMAIN` خوانده می‌شود، اما
**Railway این متغیر را فقط وقتی تنظیم می‌کند که سرویس واقعاً یک دامنه
`*.up.railway.app` تولیدشده داشته باشد.** اگر شما فقط دامنه شخصی اضافه
کرده باشید، این متغیر خالی است و اشتراک فقط یک دامنه خواهد داشت.

دو راه حل:

۱. Railway → Settings → Networking → **Generate Domain** بزنید و ری‌دیپلوی کنید
۲. یا دستی تنظیم کنید:

```env
ALT_HOSTS=panelgaming-production.up.railway.app
```

در صفحه **Settings** پنل، فهرست دامنه‌های فعال نمایش داده می‌شود و اگر فقط
یکی باشد هشدار می‌دهد.

### نمایش حجم و تاریخ انقضا در کلاینت

همه کلاینت‌ها هدر `Subscription-Userinfo` را می‌خوانند، ولی اکثرشان آن را
در صفحه‌ای پنهان می‌کنند. برای همین دو خط اضافه در ابتدای اشتراک می‌آید که
همان اطلاعات را مستقیم در لیست سرورها نشان می‌دهد:

```
📊 32.00GB / 100.00GB  (32%)  ·  68.00GB left
⏳ 29 days left  ·  2026-08-30
```

این دو به `127.0.0.1:1` اشاره می‌کنند، پس واضح است که اطلاعاتی‌اند و اگر
کسی روی آن‌ها بزند فوراً و به‌صورت محلی fail می‌شوند.

برای حذفشان، به انتهای لینک اشتراک `?info=0` اضافه کنید.

### روش ۱ — لینک اشتراک (بهترین روش)

آدرس پورتال کاربر را برایش بفرستید:

```
https://آدرس-شما.up.railway.app/u/توکن-کاربر/
```

توکن را از ستون Subscription در پنل بردارید. کاربر این صفحه را باز می‌کند،
پروفایل بازی‌اش را انتخاب می‌کند و لینک اشتراک را کپی می‌کند.

**مزیت:** با تغییر کانفیگ‌ها، کلاینت خودش آپدیت می‌شود.

| کلاینت | فرمت |
|--------|------|
| v2rayNG، v2rayN، NekoBox، Shadowrocket | پیش‌فرض (Base64) |
| Clash Meta، Clash Verge، FlClash | `?format=clash` |
| sing-box، SFA، SFI | `?format=singbox` |

### روش ۲ — کانفیگ تکی

دکمه **COPY** را بزنید و لینک را در کلاینت پیست کنید،
یا **QR** را بزنید و با موبایل اسکن کنید.

### کدام پروتکل را انتخاب کنم؟

| پروتکل | چه موقع |
|--------|---------|
| **VLESS + XHTTP** ⭐ | پیش‌فرض. جدیدترین، کم‌ترین سربار، بهترین پینگ |
| **VLESS + HTTPUpgrade** | سبک‌تر از WS، عالی روی اینترنت موبایل |
| **VLESS + WebSocket** | بیشترین سازگاری. اگر بقیه کار نکرد |
| **Trojan + WS** | فینگرپرینت متفاوت اگر VLESS مختل شد |
| **VMess + WS** | کلاینت‌های قدیمی |

## کلودفلر ورکر (اختیاری)

ورکر یک مسیر ورود دوم روی شبکه کلودفلر می‌دهد — گاهی سریع‌تر از Railway
است و اگر دامنه Railway مختل شد، جایگزین دارید.

### مراحل

1. وارد [dash.cloudflare.com](https://dash.cloudflare.com) شوید
2. منوی **Workers & Pages** → **Create** → **Create Worker**
3. اسمی بگذارید و **Deploy** بزنید
4. **Edit code** را بزنید، همه کد را پاک کنید و محتوای فایل
   `cloudflare-worker.js` را از ریپو کپی و پیست کنید
5. **Deploy** بزنید
6. حالا **Settings → Variables and Secrets** → این‌ها را اضافه کنید:

| Name | Value |
|------|-------|
| `UPSTREAM` | `آدرس-شما.up.railway.app` (بدون `https://`) |
| `PATH_PREFIX` | پیشوند مخفی از صفحه Settings پنل |

7. **Deploy** دوباره

### تست ورکر

```
https://اسم-ورکر.workers.dev/ping
```

باید `pong` بدهد.

```
https://اسم-ورکر.workers.dev/__status
```

باید JSON با `"reachable": true` بدهد.

### اتصال به پنل

در Railway متغیر زیر را اضافه کنید:

```env
CF_WORKER_HOST=اسم-ورکر.workers.dev
```

بعد از ری‌دیپلوی، کانفیگ‌های CF کنار کانفیگ‌های مستقیم ظاهر می‌شوند.

## قابلیت‌های جدید

### 🎮 پینگ سرور بازی‌ها
صفحه **Game Ping** پینگ از مرورگر شما به سرورهای واقعی بازی‌ها را می‌سنجد:
والورانت، CS2، **FC Mobile**، **eFootball (PES)**، **کلش رویال / CoC**،
**براول استارز**، PUBG موبایل، فورتنایت، COD موبایل، موبایل لجندز و بیشتر.

یک بار با VPN روشن و یک بار خاموش تست کنید تا بفهمید تونل چقدر برایتان
هزینه پینگ دارد.

رنگ‌ها: سبز زیر ۶۰ms، فیروزه‌ای زیر ۱۲۰ms، نارنجی زیر ۲۰۰ms، قرمز بالاتر.

### ⚡ بوست
هر کاربر می‌تواند **۳۰ دقیقه بوست** بگیرد — از پنل یا از پورتال خودش.
در این مدت آن اکانت روی یک سطح جدا از Xray می‌رود:
بافر صفر، سریع‌ترین هندشیک، بیشترین تحمل بیکاری.
شمارش معکوس زنده نمایش داده می‌شود و خودکار تمام می‌شود.

### 📊 گزارش هفتگی
برای هر کاربر: مجموع مصرف، میانگین روزانه، مقایسه با هفته قبل،
نمودار ۷ روزه، شلوغ‌ترین روز و ساعت، رنک، دستاوردها و
پیش‌بینی اینکه سهمیه چند روز دیگر تمام می‌شود.

از دکمه 📊 کنار هر کاربر یا از پورتال خود کاربر باز می‌شود.

### 📈 نمودار مصرف هر کاربر
داخل پنجره کانفیگ‌ها، تب **My Activity**: نمودار مصرف همان کاربر
در بازه ۲۴ ساعت / ۷ روز / ۳۰ روز.

### 🎁 لینک‌های تست رایگان
صفحه **Trial Links** → **New trial link**:

| تنظیم | معنی |
|-------|------|
| Quota | حجم هر اکانت تست |
| Duration | مدت اعتبار به ساعت |
| Total claims | حداکثر تعداد کل اکانت‌ها |
| Per day | سقف روزانه |

لینک را می‌دهید، هر کس بازش کند خودش اکانت می‌گیرد — بدون دخالت شما.
محافظت: هر IP روزی یک بار، سقف روزانه، سقف کل، و دکمه توقف.

### 🎨 پوسته‌ها
هفت پوسته آماده + انتخاب رنگ دلخواه، از **Settings** پنل و از پورتال کاربر:

**Neon** (پیش‌فرض) · **Matrix** · **Cyberpunk** · **Ice** · **Ember** ·
**Royal** · **Stealth**

پوسته *Stealth* افکت ذرات، اسکن‌لاین و انیمیشن لوگو را هم خاموش می‌کند —
مناسب وقتی نمی‌خواهید صفحه در نگاه اول شبیه پنل VPN باشد.

## بهینه‌سازی پینگ و پایداری

تنظیمات پیش‌فرض برای گیمینگ انتخاب شده‌اند:

**سرور (Xray)**

| تنظیم | مقدار | چرا |
|-------|-------|-----|
| `bufferSize` | **`0`** روی همه سطوح | مهم‌ترین عامل تاخیر. هر مقدار بالای صفر یعنی پکت منتظر پر شدن بافر می‌ماند |
| sniffing | **خاموش** | با `destOverride` سرور مقصد را بازنویسی و دوباره resolve می‌کرد و IP انتخابی بازی دور ریخته می‌شد |
| `domainStrategy` | `AsIs` | یک DNS lookup اضافه روی **هر** اتصال جدید حذف شد |
| `connIdle` | ۶۰۰ ثانیه | بازی‌ها وقفه‌های طولانی سکوت دارند؛ تایم‌اوت کوتاه = قطعی تصادفی |
| `uplinkOnly`/`downlinkOnly` | `0` | اتصال نیمه‌بسته وسط بازی قطع نمی‌شود |
| `tcpNoDelay` | روشن | پکت‌های کوچک بازی فوراً ارسال می‌شوند |
| `tcpFastOpen` | روشن | اولین بسته داده همراه هندشیک می‌رود، یک رفت‌وبرگشت صرفه‌جویی |
| `tcpUserTimeout` | ۱۰ ثانیه | مسیر خراب سریع fail می‌شود به‌جای فریز شدن |
| `tcpcongestion` | `bbr` | روی اینترنت موبایل خیلی سریع‌تر از cubic |
| `tcpMaxSeg` | ۱۴۰۰ | زیر MTU استاندارد، بدون تکه‌تکه شدن پکت |

**XHTTP**

| تنظیم | مقدار | چرا |
|-------|-------|-----|
| `mode` | `packet-up` | تنها حالتی که nginx سالم پاس می‌دهد |
| `scMinPostsIntervalMs` | **`2-6`** | پیش‌فرض ۳۰ میلی‌ثانیه بود — منشأ اصلی تاخیر XHTTP |
| `scMaxEachPostBytes` | ۱۰۰-۴۰۰ کیلوبایت | زودتر flush می‌شود |

**nginx**

| تنظیم | چرا |
|-------|-----|
| `tcp_nodelay on` | بدون آن nginx فریم‌های کوچک بازی را جمع می‌کند |
| `proxy_request_buffering off` | در تونل، بدنه درخواست خودِ تونل است |
| `proxy_socket_keepalive on` | nginx هرگز نباید عامل قطع تونل باشد |

**لینک‌های کلاینت**

| تنظیم | چرا |
|-------|-----|
| `alpn=http/1.1` روی WS و HTTPUpgrade و Trojan و VMess | این‌ها تک‌جریان هستند؛ h2 فقط سربار و head-of-line blocking اضافه می‌کند |
| `alpn=h2` فقط روی XHTTP | XHTTP واقعاً از مالتی‌پلکس h2 سود می‌برد |
| `?ed=2560` روی همه مسیرهای WebSocket | اولین پکت داخل درخواست upgrade می‌رود — یک رفت‌وبرگشت کامل صرفه‌جویی |
| `scy=aes-128-gcm` روی VMess | مذاکره زمان اجرا حذف می‌شود |
| بدون fragmentation روی پروفایل‌های بازی | تکه‌تکه کردن و مکث بین آن‌ها تاخیر واقعی دارد؛ فقط پروفایل Stealth آن را می‌پردازد |

## رفع مشکل

### پنل می‌گوید «ADMIN_PASS is not set»

متغیر `ADMIN_PASS` را در Railway اضافه نکرده‌اید. اضافه کنید و ری‌دیپلوی کنید.

### در لاگ نوشته «falling back to /tmp/ultra.db»

ولوم را روی `/data` مانت نکرده‌اید. مرحله ۴ را انجام دهید،
وگرنه با هر دیپلوی کاربرانتان پاک می‌شوند.

### در پنل نوشته Xray OFFLINE

به صفحه **Console** بروید و بنویسید:

```
reload
```

پیام خطا را نشان می‌دهد. معمولاً یعنی دانلود Xray موقع بیلد ناموفق بوده —
یک بار دیگر **Redeploy** کنید.

### کانفیگ وصل می‌شود ولی اینترنت ندارد

۱. پیشوند مسیر در کلاینت با **Settings → Transport paths** یکی باشد
۲. به‌جای XHTTP، **HTTPUpgrade** یا **WebSocket** را امتحان کنید
۳. مطمئن شوید پورت **443** و **TLS روشن** و SNI برابر دامنه شماست
۴. اگر `PATH_SECRET` را عوض کرده‌اید، کانفیگ‌ها را دوباره کپی کنید

### بعد از تغییر PATH_SECRET همه چیز قطع شد

طبیعی است — این متغیر عمداً همه مسیرها را عوض می‌کند.
لینک‌های **اشتراک** خودشان آپدیت می‌شوند، ولی کانفیگ‌های دستی را
باید دوباره کپی کنید.

### ورکر برای تونل‌ها 404 می‌دهد

`PATH_PREFIX` در ورکر باید **دقیقاً** با پیشوند پنل یکی باشد، همراه با
اسلش ابتدایی. با `/__status` چک کنید.

### کاربر به سهمیه رسید و قطع شد

خودکار غیرفعال شده. در پنل ویرایشش کنید، سهمیه را بالا ببرید
(یا تیک **Reset traffic counters** را بزنید) و وضعیت را **Active** کنید.

### شادوساکس وصل نمی‌شود

**در نسخه فعلی رفع شده است.** اگر هنوز مشکل دارید، کانفیگ شادوساکس را
دوباره از پنل کپی کنید — رمز کلاینت باید فرمت `serverPSK:userPSK` داشته
باشد که در نسخه قبلی فقط `userPSK` فرستاده می‌شد.

### آمار ترافیک صفر می‌ماند

هر ۲۰ ثانیه سینک می‌شود و فقط ترافیک واقعی عبوری از Xray را می‌شمارد.
اگر هیچ‌وقت تکان نخورد، احتمالاً Xray آفلاین است.
